# Aggiungere una stringa tradotta

**Fonte normativa**: [`modules/localization/README.md`](../../modules/localization/README.md)
**Esempio nel codice**: `modules/localization/backend/Resources/en.json` ·
`modules/localization/frontend/src/install.ts`

## Quando serve

Per ogni testo che l'utente legge.

**Quando NON serve**: per i messaggi rivolti agli sviluppatori — log, messaggi
di eccezione interni, testi dei test. Tradurre un log significa non poterlo più
cercare.

## Il principio

I cataloghi sono **serviti dall'API**, non compilati nel bundle: i messaggi del
server e le stringhe della UI vengono da un'unica fonte, e correggere una
traduzione non richiede una build del frontend.

Il plugin viene installato subito con un catalogo vuoto e riempito da
`loadLocale()`: una rete lenta ritarda le traduzioni, **mai il primo paint**.

## Procedura

1. **Aggiungi la chiave in tutti i file di risorse** —
   `modules/localization/backend/Resources/{en,it}.json`

   ```json
   {
     "common.save": "Save",
     "common.cancel": "Cancel",
     "errors.forbidden": "You do not have permission to do that."
   }
   ```

   Le chiavi sono **piatte e con namespace a punti**: `area.cosa`. Niente
   annidamento — una struttura piatta si cerca con un grep e si confronta fra
   due lingue a colpo d'occhio.

2. **Usala nel componente**

   ```vue
   <script setup lang="ts">
   const { t } = useI18n();
   </script>

   <template>
     <Button>{{ t("common.save") }}</Button>
   </template>
   ```

3. **Aggiungi la chiave a ogni lingua supportata.** Una chiave mancante
   **rende sé stessa**: l'utente vede `common.save` al posto di «Salva». È
   voluto — un testo visibilmente sbagliato viene segnalato, un'etichetta
   silenziosamente vuota no.

## Aggiungere una lingua

Un file `<codice>.json` in `Resources/`, con **tutte** le chiavi. Il selettore
di lingua si popola da `fetchSupportedLocales()`, quindi non c'è nessun elenco
da aggiornare a mano.

## Cosa non tradurre

- I log e i messaggi di errore interni.
- Gli identificatori, i nomi dei permessi, i valori degli enum: sono contratti.
- I testi che compaiono **solo** in strumenti di sviluppo o in Storybook.

## Come si verifica

```bash
pnpm test
pnpm -r typecheck
```

E a mano, cambiando lingua dall'interfaccia: cerca le chiavi grezze rimaste a
schermo. Un controllo rapido sull'allineamento fra le lingue:

```bash
python -c "import json;a=set(json.load(open('modules/localization/backend/Resources/en.json')));b=set(json.load(open('modules/localization/backend/Resources/it.json')));print('solo en:',a-b);print('solo it:',b-a)"
```

## Errori tipici

**A schermo compare `common.save`.** La chiave manca nel catalogo della lingua
attiva. È il comportamento previsto, non un crash: correggi il file.

**La traduzione non cambia dopo l'aggiunta.** Il catalogo arriva dall'API:
serve riavviare il backend (le risorse sono servite da lì), non il frontend.

**Hai messo il testo direttamente nel markup «per ora».** Quel «per ora» è la
ragione per cui poi si fa una caccia alle stringhe in tutto il repository.

**Hai tradotto una chiave di permesso o un valore di enum.** Sono contratti:
tradotti, smettono di combaciare fra client e server.

**Chiavi annidate copiate da un altro progetto.** Qui la struttura è piatta:
mischiarle rende inutile sia il grep sia il confronto fra lingue.
